# HTTPS on Android 6

`withNetworkSecurityConfig.js` bundles the public ISRG Root X1 and X2
certificates for the Let's Encrypt chain used by `com365.lcit.vn:4002`.

- Android 7 and newer use `network_security_config.xml`.
- Android 6 (API 23) ignores this XML. The plugin generates `LegacyTls.java`
  and calls it in `MainApplication.onCreate`, before React Native initializes.
  It installs an OkHttp client that accepts a chain validated by either the
  system trust manager or the bundled public roots. Signature, expiry and
  hostname verification remain enabled.
- Other Android versions keep the platform HTTP client.

The native directories are generated by Expo; keep these changes in the
plugin. After changing the plugin, build and install a new APK:

```sh
npx eas-cli@latest build -p android --profile preview
```

An Expo Go session or JavaScript-only update cannot apply this native fix.
Keep the API URL `https://com365.lcit.vn:4002/api`. Port 4002 expects HTTPS.
To check the generated files and TLS 1.2 certificate chain from a computer:

```sh
npx expo prebuild --platform android --no-install
node scripts/test-android-tls.cjs --live
```

For device verification, test login and an authenticated request on Android
6.0.1. If TLS still fails, inspect `adb logcat` for `SSLHandshakeException`
or `LegacyTls`, and check the phone's date and time.
